The *Universal Tablature Composer Language* is the high-level authoring format.
Source files use the `.utab` extension. A compiler resolves the musical intent,
instrument definitions, and arrangement into Universal Tablature JSON.

[NOTE]
====
This page describes the implemented `0.1-draft` text language. It is an evolving
reference rather than a compatibility promise.
====

== Lexical structure

Identifiers begin with a letter or underscore and may contain letters, decimal
digits, underscores, and hyphens. Keywords use the same lexical form as
identifiers and are case-sensitive.

String literals are enclosed in double quotes. They support `\n`, `\r`, `\t`,
`\"`, and `\\` escapes. Integer and decimal literals may have a leading `+` or
`-`. A line comment begins with `//`.

Newlines separate declarations and sequential musical expressions. A semicolon
may be used instead, which is useful for several expressions on one line. A
comma combines musical expressions in parallel.

[source,utab]
----
C4 q; D4 q       // sequential: D4 follows C4
C4 h, E4 h, G4 h // parallel: the notes begin together
----

== Document declarations

A document may contain the following top-level declarations. `module`, when
present, must appear once. Imports and declarations may follow in source order.

[source,utab]
----
module examples.twinkle
import instruments.piano

title "Twinkle Twinkle Little Star"
meter 4/4
tempo 100
scale C major

instrument piano : Piano as "Piano"

phrase melody { bar { C4 q; C4 q; G4 q; G4 q } }

section verse : 1 bars {
    piano {
        voice melody { melody }
    }
}

main { verse }
----

`module name`:: Declares a dot-qualified module name, such as
`examples.twinkle`.

`import name`:: Makes public symbols from another dot-qualified module
available to this module.

`title "text"`:: Sets the composition title.

`meter numerator/denominator`:: Sets the meter. Both values are positive
integers.

`tempo number`:: Sets the tempo in quarter notes per minute. The value must be
positive.

`scale tonic mode`:: Sets the tonic pitch class and scale name used to resolve
scale-relative notes and chords.

`instrument name : Model`:: Creates an instrument instance. Add `as "Display
name"` to set its displayed name or `fingering symbol` to select a fingering.
Model and fingering references may be local identifiers, qualified names, or
quoted stable catalogue IDs.

`main { section ... }`:: Gives the ordered section arrangement. Section names
may be separated by newlines, semicolons, or commas.

== Musical expressions

Every musical expression has a duration. Sequence duration is the sum of its
children; parallel duration is the maximum child duration.

=== Notes, rests, and durations

Absolute notes combine a pitch name and octave with a duration. Pitch classes
use `A` through `G`, with `#` or `b` accidentals.

[cols="1,2,2",options="header"]
|===
|Form |Example |Meaning

|Absolute note
|`F#4 q`
|F sharp in octave 4, quarter-note duration

|Relative note
|`@3[4] e`
|Third degree of the active scale in octave 4, eighth-note duration

|Altered relative note
|`@4#[3] h`
|Raised fourth degree in octave 3, half-note duration

|Rest
|`rest q` or `_ q`
|A quarter-note rest
|===

Duration symbols are `w` (whole), `h` (half), `q` (quarter), `e` (eighth), and
`s` (sixteenth). Append one or more dots (`q.`, `q..`) or write any positive
rational whole-note duration as `[numerator/denominator]`. Dots bind to the
duration token; `q .` is not valid.

=== Tuplets and proportional duration

`tuplet played:inTheTimeOf { ... }` scales a group proportionally. `stretch`
uses an exact rational factor; `augment n/d` and `diminish n/d` are readable
phrase-transform forms.

[source,utab]
----
tuplet 3:2 { C5 e; D5 e; E5 e }
stretch 3/2 { motif }
augment 2/1 { motif }
diminish 2/1 { motif }
----

All score time is rational. Nested tuplets and transforms compose exactly rather
than accumulating floating-point timing error.

=== Ties and partial bars

A postfix `~` ties a note to the next adjacent occurrence of the same resolved
pitch. It produces one sustained attack while retaining both written segments
for editing. Chord ties sustain only pitches shared by the two realized
voicings.

`pickup { ... }` and `final { ... }` assert incomplete boundary bars. In a
section they must occur at the beginning and end respectively, and their
durations must complement one another under the applicable meter.

[source,utab]
----
pickup { G4 q }
bar { C5 h.; C5 q~ }
bar { C5 q; D5 h.; }
final { E5 h. }
----

=== Chords

An absolute chord has the form `chord root quality duration`. A relative chord
starts with a scale degree. `using` selects a named instrument-specific shape.

[source,utab]
----
chord C major w
chord F# minor h
chord @5 dominant7 q
chord G major w using cowboyG
----

Chord quality is an identifier resolved by the semantic layer. Common built-in
qualities include `major`, `minor`, `diminished`, `augmented`, `dominant7`,
`major7`, `minor7`, `sus2`, and `sus4`.

=== Grouping and reuse

`bar { expressions }`:: Groups expressions into an explicit bar. Its resolved
duration must match the active meter.

`( expressions )`:: Groups a sequence as one expression.

`repeat count { expressions }`:: Repeats a sequence a positive number of times.

`phrase name { expressions }`:: Declares a reusable sequence. Writing the phrase
name as an expression references it.

`phrase name(label: pitch, count: integer) { ... }`:: Declares a parameterized
phrase. Calls use matching labels, for example `name(label: C4, count: 2)`.

`transpose pitch n semitones { ... }`:: Chromatically transposes notes, chord
roots, explicit basses, and pitch ranges after phrase expansion.

`transpose degree n { ... }`:: Moves scale-relative material by scale degrees,
crossing the tonic when necessary while retaining chromatic alteration.

`perform pattern { chords }`:: Applies a declared performance pattern to a chord
progression.

=== Direct actuator interactions

An interaction can directly address an instrument actuator using
`action target duration`. Targets use the same canonical path and single-member
selector syntax as Universal Tablature JSON.

[source,utab]
----
pluck strings[9] q
strike surfaces["snare-head"] q
press manuals.upper.keys[3] h
----

The selector may be a positive one-based integer or a quoted member name. Omit
the selector to address the complete group. The action and target are validated
against the surrounding instrument's profile, and the exact coordinate survives
lowering. See the link:/en/tutorials/hurrian-hymn/[Hurrian Hymn tutorial] for a
score whose source material is best represented as instrument coordinates.

== Sections, instruments, voices, and lyrics

A section establishes a shared timeline. Instrument blocks in the section run
in parallel; each instrument contains one or more voices, which also run in
parallel.

[source,utab]
----
section chorus : 2 bars {
    harmony {
        chord C major w
        chord G major w
    }
    piano {
        voice rightHand { melody }
        voice leftHand  { accompaniment }
    }
    singer {
        voice melody {
            lyrics { "Twin-kle twin-kle"; "lit-tle star" }
            melody
        }
    }
}
----

The optional `: count bars` annotation declares the section length. A `harmony`
block records harmonic expressions independently of an instrument voice.
`lyrics` contains one or more quoted strings and belongs to the surrounding
voice.

== Context changes and expressive performance

Meter, scale, and tempo directives inside a sequence affect following siblings.
They are forbidden in parallel branches because simultaneous conflicting
context would be ambiguous. Inline meter changes must occur at bar boundaries.

[source,utab]
----
bar { C4 w }
meter 3/4
bar { D4 h; E4 q }
tempo q. = 80
tempo ramp to 120 over w steps 4
----

`fermata duration factor number` and `rubato duration factor number` alter
performed time while preserving written score duration. The compiler emits
tempo-map changes and an exact restoration point.

Dynamic declarations use standard levels such as `pp`, `p`, `mp`, `mf`, `f`,
and `ff`. A `using dynamics` declaration applies to its complete enclosing
sequence; a `dynamics` block is local. `crescendo` and `diminuendo` interpolate
attack intensity by score position.

[source,utab]
----
using dynamics mf
C4 q
dynamics p { D4 q; E4 q accent }
crescendo to f { F4 q; G4 q }
pedal { C4 h; E4 h }
----

`using legato`, `legato { ... }`, and `slur { ... }` retain phrasing intent.
Postfix `rearticulate` forces a new attack. Postfix `letRing` extends performed
duration until a zero-time `damp` interaction or the section boundary, without
changing written duration.

Any technique declared by the active instrument profile can be applied as a
named block, for example `vibrato { A4 h }`, `pizzicato { D4 q }`, or
`doubleStop { ... }`. Unsupported names are diagnosed during instrument
realization. `hammerOn { from; to }` and `pullOff { from; to }` are retained as
two-endpoint transition techniques. Bends and slides carry typed transition
configuration: `bend(semitones: 2) { A3 q }` and
`slide(to: A3) { F#3 q }`.

Technique arguments describe non-temporal configuration or a destination;
expressions inside the block are performed material and therefore own duration,
voice, instrument context, and the transition's starting state. A bend is
normally specified relative to its performed note, so its semitone distance is
an argument. A slide can target a pitch or a physical coordinate. Parallel
strings use an ordered coordinate list whose entries correspond to the parallel
block operands:

[source,utab]
----
slide(to: [strings[1].frets[5], strings[2].frets[7]]) {
    F#3 q, B3 q
}
----

=== Grace notes and ornaments

[source,utab]
----
grace stealFollowing e { D5 s; E5 s }
C5 h
ornament trill s { D5 q }
ornament mordent s { E5 q }
----

`stealFollowing` delays and shortens the principal event within an explicit
budget. `beforeBeat` places the grace budget immediately before its anchor;
`measured` contributes its authored durations to written time. Supported named
ornaments are `trill`, `mordent`, `turn`, and `appoggiatura`; the subdivision is
explicit and must be shorter than the decorated note.

== Constants and custom scales

`let` declares integer, pitch-class, scale-degree, or chord constants.

[source,utab]
----
let tonic = C
let dominant = @5
let V = chord @5 major
let midiProgram = 25

scale maqamRast = cents { 0, 204, 386, 498, 702, 884, 1088 }
----

A custom scale declaration defines the cent offsets within an octave. Select it
with a top-level declaration such as `scale C maqamRast`.

== Scoped note naming

Naming conventions are library values, not global parser modes. Importing a
module makes its table available; `using notation` selects it lexically.
Declarations bind names where they are authored, so an imported or reused
phrase is never reinterpreted under its caller's notation.

[source,utab]
----
import std.naming.western.german
import std.naming.solfege.movable

phrase answer {
    using notation German
    H4 q; Fis[4] q
}

phrase response {
    using notation MovableSolfege
    do[0] q; mi[0] q
}
----

The standard library also provides fixed solfège and contextual Arabic degree
names. The latter follow the active scale and do not assert one universal
intonation for Arabic pitch names.

== Advanced harmony and voicing

Import `std.harmony.chords` for the standard open chord-quality collection and
`std.harmony.bass` for data-driven bass patterns. Chords support slash basses,
inversion, omission, doubling, range constraints, added or altered tones, and
nearest voice leading.

[source,utab]
----
chord A/G major h
chord C dominant7 h alter 5b add 9#
chord @2 minor w bass F inversion 1 omit 5 double 3 range C4 C6
using voiceLeading nearest
bass rootFifth q octave 2 { chord C minor w }
----

`chordQuality` and `bassPattern` declarations allow libraries and scores to add
new interval collections and accompaniment patterns without compiler changes.

== Performance patterns

A performance pattern divides each input chord into equal steps. A step names
an interaction; steps in parentheses and separated by commas occur in parallel.

[source,utab]
----
performancePattern downUp {
    subdivision e
    steps {
        strum down
        strum up
        (strum down, strum up)
    }
}
----

== Instrument catalogue declarations

Composer modules can define the instrument catalogue used by scores.

`profile Name { ... }`:: Defines actuator capabilities, interactions, and
techniques. Profile items include `actuator`, `interaction`, and `technique`.

`model Name : Profile { ... }`:: Defines an instrument model conforming to a
profile. Model bodies contain properties and `geometry name { ... }` blocks.

`extension Model { ... }`:: Adds `tuning`, `fingering`, or `chordShape`
definitions to a model.

Properties accept identifiers, strings, integers, decimals, qualified symbol
references, or comma-separated values. The meaning and validation of individual
properties depends on the surrounding declaration.

[source,utab]
----
model Guitar : FrettedStrings {
    id "instrument:guitar:classical-six-string"
    name "Six-string Classical Guitar"
    geometry strings { count 6 }
    geometry frets { count 19; movable false }
}

extension Guitar {
    tuning standard default {
        id "tuning:guitar:standard"
        tags guitar, standard
        course E2
        course A2
        course D3
        course G3
        course B3
        course E4
    }
    chordShape cowboyG : G major {
        string 6 fret 3
        string 5 fret 2
        string 4 fret 0
        string 3 fret 0
        string 2 fret 0
        string 1 fret 3
    }
}
----

== Compilation model

Compilation parses and validates Composer source, expands references and the
`main` arrangement, resolves scales and chords, realizes notes for concrete
instruments, and emits link:/en/reference/json/[Universal Tablature JSON]. Diagnostics use
one-based line and column positions. Source references may be preserved in the
JSON editing map so authoring tools can trace resolved events back to Composer
declarations.
